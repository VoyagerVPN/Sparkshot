# Sparkshot

Портативный нативный скриншотер Windows на C++20 и Win32/Direct2D.

Принятые требования: скриншотер без подсистемы заметок ClipNote; пипетка, быстрое рисование, плавная рамка; Ctrl+Z для отмены и Ctrl+Y/Ctrl+Shift+Z для повтора; имена `Screenshot_номер.png` совместимы с Lightshot, существующие файлы никогда не перезаписываются.

Сборка: `build.cmd` (MSVC Build Tools 2026, Windows SDK). Кэш и сборочные результаты находятся в `.cache`. Runtime C++ включается статически.

Язык интерфейса выбирается кнопками **English / Русский** в настройках и сохраняется в `data/settings.ini` рядом с EXE. При первом запуске используется язык интерфейса Windows, если это русский; для остальных языков выбирается английский. Собственные строки приложения находятся в ресурсах Win32 `src/localization-strings.rc`. Системный диалог выбора папки запрашивается на выбранном языке и зависит от установленных языковых ресурсов Windows.

Проверка локализации: `build.cmd build-l10n SparkshotLocalizationTest`, затем `.cache\build-l10n\SparkshotLocalizationTest.exe`. Проверка охватывает выбор языка по настройке и языку Windows, наличие ресурсов обоих переводов и подстановки в переведённые сообщения.

Прототип 0.1.8: панели, палитра и иконки редактора рисуются средствами Direct2D. Основная стрелка, палец и указатели действий — системные, с темой и размером пользователя. Окно выбора папки оставлено системным по решению пользователя. Установка, Electron, WebView и отдельный VC Runtime не требуются.

Исправление от 05.10.2026: эксперимент с принудительной отрисовкой редактора на CPU заменён аппаратным Direct2D/D3D11. На синтетической области 6400×2015 программный режим тратил около 10–11 мс на рисование кадра, что превышает бюджет 6,06 мс для 165 Гц. Теперь неизменная сцена кэшируется, движение указателя обновляет только затронутую область, а вывод через DXGI flip-model допускает максимум один кадр в очереди. Обработка ввода продолжается при ожидании готовности вывода; новые изменения объединяются перед рисованием. Аппаратный режим используется по умолчанию, WARP — резерв при недоступности аппаратного устройства. Экспорт остаётся программным и выполняется только по команде пользователя. Блокирующее `DwmFlush` перед чтением экрана удалено; порядок захвата сохранён.

Графическое устройство создаётся один раз при запуске процесса и сохраняется между захватами. Закрытие редактора освобождает поверхности и состояние снимка отдельно; полный сброс устройства выполняется при ошибке рендера или завершении приложения. Фонового рисования для прогрева и искусственной задержки перед захватом нет.

Каждый новый захват начинается с инструмента «Выбор», независимо от последнего выбранного инструмента. Пипетка показывает контрастный прицел с белым пикселем в центре; он совпадает с пикселем, из которого берётся цвет. Лупа увеличивает сетку 21×21 в шесть раз: рамка выделяет центральный пиксель, а у краёв изображения остаются пустые клетки, чтобы центр и масштаб не смещались. Изолированная проверка редактора проходит 29 сценариев на GPU и 29 на WARP: новый и повторный захват, перемещение рамки, соседние пиксели пипетки, последнее состояние после серии движений, восстановление фона под указателем, рисование, ластик, история, простой без активного цикла, PNG без интерфейса и копирование в буфер обмена. Отдельная серия из 6 проверок на каждом режиме проверяет смену изображения и размеров. Проверки работают через сообщения скрытого окна с настоящим DXGI; физический ввод и Computer Use не используются. Команды: `build.cmd build-0.1.8-device-reuse SparkshotTestHost`, затем `python -B tests/editor-smoke.py .cache/build-0.1.8-device-reuse/Sparkshot.exe` и та же команда с `--warp`. Новый захват готовит и отправляет первый свежий кадр до показа окна, чтобы не отображать сохранённое содержимое предыдущего захвата. Проверены первый кадр повторного захвата и первый кадр после закрытия редактора. Наблюдаемая плавность на 165 Гц, работа в игре и предельное заполнение VRAM остаются за ручной проверкой пользователя. Подробности замеров: `work/fix-2026-10-05-frame-pacing.md`; исправление первого кадра: `work/fix-2026-10-05-fresh-capture.md`; ускорение открытия: `work/fix-2026-10-05-device-reuse.md`.

В 0.1.8 захват сначала считывает экран, затем очищает прежний редактор и открывает выделение поверх готового снимка. Поэтому настройки, меню трея, палитра и редактор Sparkshot могут попасть на снимок, если были видимы в момент запуска захвата. Раньше Hide вызывался до чтения экрана, и собственный интерфейс исчезал из снимка. Меню трея больше не скрывается просто из-за потери фокуса; его можно закрыть Esc или выбором команды. После захвата, начатого из настроек или меню трея, копирование, сохранение и закрытие захвата возвращают соответствующее окно на прежнюю позицию. Ошибка чтения экрана не уничтожает прежнее окно и текущую разметку. Показ самого приложения в новом снимке отличается от временных направляющих текущего редактора: видимый интерфейс предыдущего захвата может стать частью фона нового снимка при повторном захвате.

Окно настроек 0.1.8 переработано: размер 680×664, крупный заголовок, три отдельные карточки «Захват экрана», «Сохранение», «Автозапуск». У каждой карточки своя векторная иконка, заголовок и описание. Клавиша находится в отдельном поле с кнопкой «Изменить», папка — в строке пути с кнопкой «Выбрать». Для автозапуска предусмотрен переключатель, путь текущего EXE и отдельное отключение старой привязки. Длинные пути сокращаются многоточием с сохранением конца пути. Служебные сообщения показаны отдельно внизу; изменения применяются сразу. Кэш геометрии иконок охватывает все добавленные типы.

Начиная с 0.1.3 штрих не строится заново из перекрывающейся геометрии на каждом кадре. Карандаш и ластик дописывают только новые участки в альфа-маску; перед кадром обновляется изменённый прямоугольник текстуры. Колесо обновляет локальный участок, уже нарисованная часть сохраняет прежнюю толщину. Законченные маски обрезаются по границам штриха и разделяются между состояниями истории. Проверка попадания в штрих использует готовую маску. Геометрия иконок и стиль их линий также кэшируются. Реальное ускорение на компьютере пользователя ещё не измерено.

Карандаш, линия, стрелка с острым заполненным наконечником, прямоугольник, ластик, текст, пикселизация, нумерация, пипетка, эллипс и заливка ведром. Маркер удалён по решению пользователя. Панель расположена в один вертикальный ряд. Во время создания выделения сразу видны рамка, её размеры и все восемь ручек изменения размера; инструменты появляются после отпускания кнопки мыши и остаются видимыми при рисовании и изменении размера готовой рамки. Заливка по клику учитывает исходный снимок и текущую разметку, ограничена выделением и использует допуск 16 на каждый канал RGB. Залитый прямоугольник заменён заливкой.

При удержании Tab внутри рамки отображаются четыре временные направляющие: между серединами верхней и нижней сторон, между серединами левой и правой сторон и обе диагонали. Они следуют за рамкой во время выделения, изменения размера и перемещения. Нажатие и отпускание Tab сразу обновляют кадр без движения мыши, в том числе при вводе текста/HEX. При потере фокуса направляющие скрываются. Они не входят в снимок и историю.

Shift при рисовании прямоугольника задаёт квадрат, при рисовании эллипса — круг. У линии и стрелки Shift фиксирует направление с шагом 45 градусов. Нажатие и отпускание Shift обновляет предпросмотр даже без движения мыши; при отпускании кнопки мыши сохраняется текущая форма.

Ластик кистью убирает разметку под штрихом, восстанавливая исходный снимок; обычный ластик показывает круг без точки. При удержании Shift тот же круг получает точку в центре и значок корзины; Shift+клик удаляет целую фигуру. Номер до клика показывает следующий значок в месте установки и метку центра, заливка — прицел с точкой целевого пикселя. Для карандаша, ластика, линии, стрелки, прямоугольника и эллипса отображается контур толщины и размер в пикселях до начала рисования и во время него. Небольшой значок инструмента возле указателя не имеет подложки. Колесо и Ctrl+колесо меняют толщину прямо во время штриха, сохраняя толщину уже нарисованных участков. Для пикселизации они отдельно меняют размер блока, в том числе во время выделения области.

Общий курсор-крестик и собственная стрелка удалены. Кнопки, цветовые слоты, поле оттенков и шкала яркости используют системный курсор-палец; изменение размера, перемещение и ввод текста — соответствующие указатели Windows. Там, где на холсте рисуется указатель инструмента, системный курсор скрыт. Ластик в обоих режимах использует круг: без точки в обычном режиме, с точкой и корзиной при удержании Shift. Alt переключает пипетку и обратно непосредственно по событиям клавиатуры, с обновлением кадра без ожидания движения мыши. При активном вводе текста Alt+перетаскивание перемещает текст. Shift+колесо выбирает предыдущий/следующий инструмент в панели, с переходом через её края; выполняющийся штрих не прерывается переключением. Эффективная задержка этого выпуска ещё не измерена.

Исправление совместимости с установленной Caramba Switcher от 02.10.2026: её программный Ctrl+C с меткой 0xCA7E не запускает копирование снимка и не завершает захват. Переключатель использует эту команду для чтения выделенного текста через буфер обмена. Обычное Ctrl+C в текстовом поле копирует выделенные символы, а при пустом выделении — готовый снимок. Метка проверена по декомпилированной установленной версии Caramba; совместимость с будущими версиями переключателя требует повторной проверки.

Текст редактируется прямо на снимке: прозрачная область с тонкой рамкой, выделением и кареткой, без отдельного окна, тени и фона. Колесо и Ctrl+колесо меняют размер шрифта сразу в предпросмотре (8–192 px), включая уже введённый текст. Alt+перетаскивание в рамке перемещает активный текст без завершения ввода. Enter завершает, Shift+Enter вставляет новую строку, Esc отменяет редактирование. Ctrl+C с выделенными символами копирует текст, без выделения — снимок; Ctrl+S сохраняет снимок и во время ввода. Инструментом «Текст» можно нажать на ранее добавленный текст и изменить его; отмена сохраняет исходный объект, завершённое изменение входит в историю. Для ввода и работы с буфером текста используется нативный EDIT, а видимое содержимое, готовая аннотация и экспорт PNG рисуются одинаковым DirectWrite с одним размером и сглаживанием.

Панель содержит кнопки отмены и повтора. История хранит до 128 законченных действий; рамка выделения в неё не входит. Данные законченных фигур разделяются между состояниями истории, их отрисовка кэшируется до следующего изменения.

ПКМ внутри редактора открывает компактную палитру 220×390: прямоугольное поле оттенков и насыщенности по примеру Paint, отдельная вертикальная шкала «Яркость», 24 готовых цвета, HEX и 12 своих слотов. По горизонтали поля выбирается оттенок, по вертикали — насыщенность (насыщенные цвета сверху, белые снизу). Шкала яркости показывает выбранный оттенок от светлого сверху до чёрного снизу; значение меняется кликом, перетаскиванием или колесом. Неясный процент в заголовке удалён. Большое поле кэшируется независимо от выбранного цвета; при смене оттенка/насыщенности обновляется только узкая шкала. Оба градиента обновляются до начала кадра Direct2D. Каждый пустой слот «Свои цвета» содержит «+»: нажатие сохраняет текущий цвет именно туда. Нажатие на заполненный слот выбирает цвет; маленький крестик справа сверху освобождает этот слот. ПКМ больше не удаляет цвета. Остальные слоты не сдвигаются; они хранятся в data/settings.ini, включая пустые позиции. Старый список цветов поддерживается. При обновлении следует сохранять папку data.

`Ctrl+Alt+S` — захват по умолчанию (можно изменить в настройках); `Ctrl+C`/Enter — копирование снимка в буфер обмена (CF_DIB + CF_DIBV5 + PNG); `Ctrl+S` — сохранение PNG; `Ctrl+Z` — отмена; `Ctrl+Y` и `Ctrl+Shift+Z` — повтор; `Alt` — временная пипетка или перемещение активного текста; `Shift+колесо` — выбор инструмента; `Ctrl+колесо` — размер кисти или текста; `F2` — выбор папки; Esc — закрыть палитру/захват. Значок в трее: двойной щелчок — захват, ПКМ — меню, «Выход» — завершение.

ПКМ по значку в трее → «Настройки»: автозапуск, текущий путь EXE, папка сохранения и изменение клавиши захвата. Нажмите строку клавиши и введите новую клавишу/сочетание, например Print Screen; Esc отменяет выбор. Windows проверяет регистрацию сочетания. При отказе или ошибке записи настроек прежняя регистрация восстанавливается; на экране видна причина. Новая клавиша и модификаторы сохраняются в data/settings.ini вместе с остальными настройками. Меню трея и подсказка значка отображают сохранённое сочетание.

Автозапуск выключен, пока пользователь сам его не включит. При включении записывается только значение Sparkshot в HKCU\Software\Microsoft\Windows\CurrentVersion\Run: полный путь к текущему EXE в кавычках и --autostart. Администраторские права не нужны. При входе в Windows Sparkshot остаётся в трее и не начинает захват; если экземпляр уже запущен, повторный автозапуск тоже не открывает снимок. После переноса приложения запустите его из новой папки и включите автозапуск для этой копии: старый путь заменится. Настройки распознают запись другой копии и дают обновить либо отключить её; другие записи автозапуска не меняются. Ограничение команды Run — 260 символов, при превышении показана ошибка. Механизм: [Run and RunOnce Registry Keys](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys).

По умолчанию используется папка из настроек установленного Lightshot, прочитанных без изменения. Если её нет — `Screenshots` рядом с EXE. Файлы получают имя `Screenshot_номер.png`: следующий номер после наибольшего существующего. Создание через `CREATE_NEW` запрещает перезапись даже при одновременном сохранении. Настройка выбранной папки хранится в `data/settings.ini` рядом с EXE; путь внутри комплекта записывается относительным.

Для выпуска в отдельном каталоге, когда старая сборка открыта: `build.cmd build-0.1.8`. Результат — `.cache/build-0.1.8/Sparkshot.exe`. Исследовательские материалы в `work` и `.cache` не входят в поставку.

Исправление и проверка от 14.10.2026: копирование размещает снимок выделения тремя форматами — CF_DIB и CF_DIBV5 с нижним порядком строк (положительная высота, как у GDI-приложений вроде Lightshot и системного Print Screen) и зарегистрированный формат "PNG" с файловым потоком. Прежний одиночный CF_DIB с отрицательной высотой (верхний порядок строк) корректно читался Paint и GDI, но не всеми читателями буфера: вставка «как картинка» не работала в приложениях на Chromium/Electron, включая ZCode. Копия PNG заметно не замедляет копирование: кодирование уже используется сохранением. Изолированная проверка читает реальный буфер после копирования: наличие всех трёх форматов, размеры и пиксели DIB (с обращённым порядком строк), заголовок DIBV5 и сигнатуру PNG-блока.

Проверка исходного выпуска 0.1.8: успешная сборка C++ x64 Release; пользователь выполнял проверку интерфейса самостоятельно. Для исправления от 02.10.2026 дополнительно проверено отдельное демо-окно: видимость указателей всех 12 инструментов, возврат системного курсора на панель и ручки рамки, защита от воспроизведённого Ctrl+C Caramba, сохранение текстового редактора и обычного копирования снимка. Полный сценарий с физическим двойным Shift в работающей Caramba, PNG, несколько мониторов, история и производительность повторно не проверялись. Перед запуском нового EXE следует завершить предыдущую сборку через её меню в трее, иначе единственный экземпляр активирует старое окно.
